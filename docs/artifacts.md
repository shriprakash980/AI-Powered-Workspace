# DevPilot AI — Build Artifact Storage & Management

## Overview

The DevPilot AI Artifact Subsystem handles production build binaries (`JAR`, `WAR`, `ZIP`, `TAR`, `DOCKER_IMAGE`, `STATIC_FILES`) generated by the build system.

---

## 1. Storage & Integrity

- **Local Storage Provider**: `LocalArtifactStorage` persists build artifacts in the local workspace storage directory structured as `<projectId>/<buildId>/<filename>`.
- **Integrity Verification**: Generates SHA-256 cryptographic checksums for every artifact upon creation to guarantee binary integrity and prevent tampered deployments.
- **Artifact Metadata**: Persisted in the `artifacts` table containing size in bytes, checksum, storage key, and artifact type enum.

---

## 2. Artifact Lifecycle

1. **Generation**: `BuildRunner` packages successful build output.
2. **Registration**: `ArtifactService` saves file stream, computes checksum, and persists DB record.
3. **Deployment**: `DeploymentService` resolves requested build artifact for container deployment or rollback.
4. **Retention**: Outdated artifacts are purged automatically according to workspace storage quota rules.
